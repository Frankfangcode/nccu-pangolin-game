# 核心玩法提案：穿山甲的校園一日

狀態：研究與提案，尚未實作；待確認本輪新玩法方向。既有地圖、美術與三件惡作劇沿用。

- 以下「目標 → 冒險 → 收穫 → 成長」是設計分析，不宣稱為官方定義。本輪沒有親自遊玩原作。

## 建議核心循環
基地接任務 → 選擇校園路線 → 觀察人類、潛行找物／搞怪 → 遭懷疑時繞路或躲藏 → 帶收穫回基地 → 換取升級 → 休息開始下一天。

玩家反覆進行的這組行動就是核心循環，像桌遊每回合「出門拿東西、帶回交換、準備下回合」。目的在於讓校園探索具有取捨與持續動機。

## 第一個可玩版本的具體範圍（建議值）
1. 基地有明確的今日目標：完成一件既有惡作劇、帶回三枚落葉徽章。徽章是遊戲虛構收藏品，不是現金。
2. 山下設置六處收集點，每點每天取一次；首次路線集中校門、四維堂、圖書館、操場一帶。全校仍可自由探索。
3. 背包起始四格：玩家決定繼續冒險或回家交付。回基地兌換徽章為夥伴點數。
4. 食物使用蟻窩／白蟻覓食意象；飽足度緩慢下降、覓食恢復。第一版不因飢餓直接判輸，只降低移動速度並提示回家。具體食性與呈現需製作前核對可靠動物資料。
5. 追捕分為安全、懷疑、追逐、搜尋。建築阻擋視線，躲到花叢並蜷縮才安全；保留原因提示。現有五名人類先調整路線、視線與搜尋時間，避免無目的增加數量。
6. 被抓回基地，損失一枚未交付徽章；已兌換點數、購買項目、探索紀錄保留。不得讓低資源玩家無法繼續。
7. 第一批兩種升級：背包四格升六格；校園吉祥物裝可延緩一般人的懷疑，但搞怪時仍會暴露。服裝是卡通設定，需原創生成穿著外觀。
8. 基地手動休息結束一天，刷新收集點與當日任務。第一版無強制倒數，以免與全校長距離探索衝突。
9. 自動儲存於此裝置此瀏覽器，沒有帳號或雲端同步。關閉再開保留點數、升級、日次、已交付任務與地點；需要有損毀／不支援儲存時的提示和安全退路。重開新進度須明確確認。

建議分兩個可驗收步驟：先完成收集、背包、交付、升級背包、被抓代價與存檔的閉環；再加入覓食、吉祥物偽裝、日次刷新。每步都需能玩完，不能只做按鈕。

## 系統與資料流
輸入／畫面 → 遊戲規則（移動、巡邏、收集、交付）→ 玩家進度（背包、點數、升級、日次）→ 畫面更新與本機存檔。
地圖提供位置與遮擋；生成素材只負責外觀。全部沿用現有瀏覽器方案，不新增伺服器或外部服務。

## 方案取捨
- 推薦：生活探索＋潛行成長。持續動機較完整；需新增背包、升級與儲存，工作量較大。
- 備援：短關卡惡作劇。每局三件任務、結算評分；改動少、容易重玩，但長期成長較弱，校園各區較難形成不同用途。

## 驗收計畫（尚未執行）
- 用真實操作完成：接目標→取物→背包滿提示→躲巡邏→回家交付→購買升級→重新開啟仍保留。
- 被抓只扣指定未交付物品，不扣已兌換點數；同一物品不能重複領取或重複結算。
- 追逐中不能靠換裝立即消除警報；穿裝與未穿裝的懷疑速度不同且畫面清楚。
- 暫停／地圖／背景分頁不能暗中耗盡飽足度；休息不造成重複獎勵。
- 存檔損毀、瀏覽器拒絕儲存仍能開始遊戲，明示未儲存；不得默默刪除有效舊進度。
- 行為以逐項紅→綠測試實作，收尾全測；桌機／手機兩輪視覺驗收，必要時補與存檔相連的資安檢查。

## 情境審查與限制
初次玩家需在出生點看到下一步；熟練玩家需能自行改路線。遊戲設計角度關注「收穫值得冒險、被抓可迅速再試」；均為 AI 設計審查，尚無玩家試玩數據。
存檔只信任經驗證的數值與已知物品代碼，限制資料大小與版本，避免損毀資料破壞遊戲狀態。這是待實作風險與驗證計畫，不是已通過的安全證據。
未加入車輛、打工職業、釣魚或建築室內；這些屬後續擴充選擇。
